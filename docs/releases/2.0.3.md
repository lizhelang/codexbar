# v2.0.3：1.05M 上下文预设与性能、界面改进

本版本修复自定义上下文输入被本地模型缓存上限拦截的问题，并包含 v2.0.2 之后已合并的用量采集性能和界面改进。

## 上下文设置

- 上下文菜单提供 **1.05M（1,050,000 tokens）** 预设，数值与[官方模型规格](https://developers.openai.com/api/docs/models/gpt-6-astra)一致，不再因本地缓存标示 872k 而隐藏。
- 修复输入 `1m`、`1M` 或更大的有效值时误报“上下文窗口无效”的问题；支持 `1.05m`、整数及带分隔符的写法。
- 超过本地模型目录标示范围时，显示具体上限并要求确认，确认后按当前模型保存。设置值不会扩展模型自身能力，实际可用长度仍取决于 Codex 和服务商。
- 非预设的自定义值也会显示在菜单中并标记选中；取消操作不改写设置，“模型默认”可清除当前模型的覆盖值。
- 极大数值会被安全拒绝，避免整数转换导致应用崩溃。

对应问题：[#62：自定义上下文大小不支持 1m](https://github.com/lizhelang/codexbar/issues/62)。

## 用量采集与后台性能

- 用量文件没有变化时跳过重复扫描，并保留定期复查；无法监听的来源继续按原方式采集。
- 对已读取的会话和用量记录复用解析缓存，减少重复解析与解压。
- 用量内容不变时减少无效界面刷新、菜单栏图标重绘和缓存写盘。
- 修复会话日志在同一路径被替换或重写后仍沿用旧运行状态的问题；正常追加继续使用增量读取，替换、等长改写和截断会重新解析。

以上来自已合并的 [#61](https://github.com/lizhelang/codexbar/pull/61)，未据此宣称固定比例的速度或资源占用改善。

## 字号与操作区域

- 菜单最小字号提高到 10pt，使小字更易读。
- 更多账号、用量和重置卡视图跟随界面字号设置。
- 常用图标按钮的点击区域统一为 24pt。

以上来自已合并的 [#64](https://github.com/lizhelang/codexbar/pull/64)。

## 安装与验证边界

- 版本：**2.0.3（build 77）**；提供 Apple Silicon 与 Intel 通用的 DMG、ZIP 和 `SHA256SUMS.txt`。
- 安装包使用 ad-hoc 签名，未使用 Developer ID 签名或 Apple 公证。
- 应用内更新会检测新版本并引导下载安装包，安装仍由用户完成。
