# v2.0.1：统一页面导航与多工具账号管理

v2.0.1 将账号管理与用量页面集中到顶部下拉菜单，并补齐五类 AI 软件的账号、额度和连接管理。以下为相对 v2.0.0 的变化。

## 主要变化

### 八个页面统一切换

- 顶部下拉菜单替代“管理 / 看板”开关和底部导航，默认顺序为：**额度、统计、工具、模型、项目、会话、设备、趋势**。
- 原管理页更名为“额度”，原看板主页更名为“统计”，删除重复的看板额度页，其余页面保留。
- 首次使用新导航时打开额度页；之后记住上次选择。已经选择统计页的用户，再次打开时仍停留在统计页。
- 当前页按钮显示页面图标与名称。展开菜单时，选中项显示系统勾，未选中项显示各自图标；选择框使用更紧凑的宽度。
- 原有自定义页面顺序、统计模块和显示偏好继续沿用。旧默认顺序自动调整为额度在前、统计第二；额度和统计始终保留。
- 所有页面共用滚动区域，移除底部导航后可显示更多内容，保留底部拖拽高度手柄。

### 五类软件在额度页直接管理

- Codex、Claude Code、OpenCode、Cursor、DeepSeek Harness 采用统一的软件分段。点击标题即可在本页展开或收起账号内容，各软件分别记住状态。
- “排序”模式使用上下箭头调整五个软件的顺序，保存后重新打开仍生效；暂停的软件也保留管理入口。
- 额度页顶部显示所选时间范围的 Token、估算费用、速率和来源状态，支持今天、本周、本月、总计及 Token / 费用切换。
- 账号内容直接放在外层滚动区域中。添加或更新凭据仍使用表单，目录与 CSV 等配置集中在“读取设置”。

### Codex 账号与额度展示更完整

- 账号列表显示普通额度窗口、GPT Reserve、各窗口重置时间、更新时间和可用重置卡数量。未知额度仍显示未知，普通额度与 Reserve 分别处理。
- Codex 收起后仍显示当前账号、剩余额度，以及模型、推理强度、服务档位和上下文控件；展开后显示完整账号列表、重置卡与第三方服务。
- “连接中转站”在收起状态下也可用。账号切换、聚合模式、刷新、重新登录和删除入口保留。
- 账号卡片第二行显示账号别名。现有邮箱 / 名字显示偏好继续用于身份展示。
- 保留 v2.0.0 已有的按账号选择 GPT Reserve、聚合额度预留比例和手动额度对齐能力。

### 多工具账号与连接管理

| 软件 | 新增或完善的管理能力 |
| --- | --- |
| Cursor | 自动识别桌面登录；手动添加 Cookie / JWT；账号改名、暂停，更新或删除手动凭据；选择用于看板的监测账号 |
| Claude Code | 自动发现本机 OAuth；手动保存网站 sessionKey 并明确选择组织；清除手动凭据后恢复自动发现 |
| OpenCode | 自动识别 Go 接入；保存命名连接，支持 Go API Key 和网站 Cookie；改名、排序、暂停、更新、移动凭据与删除 |
| DeepSeek Harness | 显示本地服务余额快照；发现明确绑定官方地址的 API Key；手动保存或清除官方 DeepSeek API Key，查询官方余额 |

- Cursor 按稳定用户 ID 分别保存套餐、额度和历史。CSV 导入绑定明确选中的账号，再次导入替换该账号历史；账号查询失败只保留该账号自己的缓存。选择看板账号不会改变 Cursor 桌面端登录。
- Claude 按所选组织查询订阅额度。多个组织时需要明确选择；API Key 不作为官方订阅账号。补齐额外用量、模型专属额度及可用重置卡信息的解析。
- OpenCode 各连接分别查询 Go 额度或网站余额；组合 API Key 与 Cookie 时需确认属于同一账号。明确绑定官方地址的 DeepSeek 接入可显示官方余额，OpenCode 内保存的 OpenAI OAuth 账号不参与 OpenCode 额度查询。
- 账号元数据和用量缓存与凭据分开保存。手动凭据文件仅当前用户可读写；凭据变更会使旧缓存失效，暂停、删除或修改连接后的迟到请求不会重新写入旧结果。

### 修复 DeepSeek Harness 重复来源与刷新含义

- 旧 `deepseek` 与新 `deepseek-official` 标识，仅在凭据来源身份相同时归并，并采用最新快照；不同身份或身份未知的来源保持独立，不按余额相同猜测账号归属。
- 自动发现的 DSH 来源支持“隐藏此来源”和“恢复已隐藏来源”。隐藏状态会保存，不删除 DSH 配置、凭据或快照。
- 本地快照按钮明确为“重读快照”，读取后保留原始余额更新时间。该操作不会把历史快照变成实时余额。
- 实时余额查询需要当前明确绑定官方地址的 Key，或手动添加官方 DeepSeek API Key。请求前复核绑定及凭据身份，自定义中转站凭据不会因历史名称被发送到官方接口。

### 其他调整

- 移除不稳定的“新开实例”功能，以及账号卡片和设置中的相关入口。
- 修复 OpenCode 网站按 `used / limit` 计算低用量百分比时的重复换算，例如 0.5% 不再显示为 50%。
- OpenCode API Key 有效但网站 Cookie 过期或返回格式异常时，保留已读取的 API 额度并明确显示错误；新增或更新连接不会保存校验失败的 Cookie。
- 暂停软件停止新的采集请求，不计入跨工具总汇总；仍可单独查看已经缓存的历史用量。
- 多工具账号接入与查询逻辑适配 Token Monitor，Cursor 用量事件分页和解析参考 tokscale。源码与应用包保留两份完整 MIT 许可证，见[第三方声明](https://github.com/lizhelang/codexbar/blob/v2.0.1/THIRD_PARTY_NOTICES.md)。

## 数据与验证范围

- 本地历史按软件汇总；Claude Code、OpenCode 和 DSH 中缺少可信账号身份的记录，不分配给手动连接。余额不换算为订阅百分比，费用估算和用量价值不等同于官方账单。
- 发布构建为 **2.0.1（build 58）**，包含 `arm64` 与 `x86_64`；严格 ad-hoc 签名、DMG 校验和 ZIP 完整性检查通过，两份第三方许可证已包含在应用中。
- 本次定向回归共 **197 项：191 项通过、6 项按条件跳过、0 失败**。全部测试源文件参与编译，覆盖账号身份隔离、连接存储、额度解析、展开与排序持久化、八页切换、默认页、原生离屏布局及旧桌面设置兼容。
- 跳过项为 1 项未开启的真实凭据联网检查和 5 项隔离测试进程无法读取的 SwiftUI 控件树检查；数据、动作和离屏渲染回归另行通过。账号名称全文 OCR 漏识别已通过同一渲染图的分区识别修正，完整名称断言保留。
- 安装后的 Codexbar 浮层读取曾持续超时；这些结果不代表真实账号联网、服务端扣账或已安装应用全部交互已经验收。详细范围见[发布验证记录](https://github.com/lizhelang/codexbar/blob/v2.0.1/docs/verification/2026-10-07-release-2.0.1.md)。

## 安装与更新

- 发布包使用 ad-hoc 签名，未使用 Developer ID 签名，也未经过 Apple 公证。macOS Gatekeeper 可能阻止首次打开，需要在“系统设置 → 隐私与安全性”中手动允许。
- 更新功能提供版本检查与安装包下载引导，需要用户继续完成安装；应用不会自动替换旧版本并重启。
