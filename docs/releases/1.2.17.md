# v1.2.17：第三方独立配置与 Responses 预设（发布说明草稿）

第三方服务改用 Codex 官方独立 provider 配置，减少切换服务对 OpenAI 登录配置的影响。新建内置预设统一使用 Responses API；Chat Completions 继续作为 Custom 中的兼容选项保留。

## 本次改进

- 普通第三方切换不再向 OpenAI 的 `auth.json` 写入第三方密钥，保留已有登录和登录备份。每个第三方服务独立保存端点和认证配置。
- 内置预设仅保留 DeepSeek、智谱 GLM、OpenRouter、Requesty。按官方 Responses 文档更新 DeepSeek、智谱和 Requesty 的端点、协议与模型选项；OpenRouter 继续使用 Responses 转发。
- Custom 默认选择 Responses；保存 Chat Completions 配置后展示明确的兼容性提示。新建 DeepSeek 配置或添加其账号时，在保存前说明官方能力限制，可选择继续保存或返回修改。
- 保留用户自行配置的 `model_catalog_json`，避免覆盖按服务商官方指南配置的模型能力目录。
- 已保存的 Chat 服务新增兼容性入口；首次识别时提示检查旧配置，切换使用前可预览并确认迁移到官方 Responses。
- Chat 转换网关增加本地请求鉴权，模型目录仅显示当前可调用模型；不再将不同模型请求悄悄替换为当前模型。
- 补齐基础 function/custom 工具的调用与结果转换；不支持的工具或不完整的上游工具响应会明确失败，普通回复里的命令文字不会被当作工具执行。

## Chat Completions 兼容性说明

Chat Completions 与 Responses 在工具和事件格式上存在差异。当前本地转换网关暂不支持多代理工具分组（`namespace`）和联网搜索（`web_search`）。**如果 Codex 默认携带这些能力，整个请求也可能报错，即使本轮只执行普通任务。** custom 工具的语法约束无法由 Chat Completions 等价保证。

关闭多代理和联网搜索后的基础命令调用与结果回传，已通过隔离 Codex CLI 和模拟上游验证；这不代表所有真实服务商、模型或 Codex 功能均已验证。为获得更完整、稳定的使用体验，建议优先选择提供 Responses API 的服务。

上述本地转换限制仅适用于 Chat Completions 路径。官方 OpenAI 和 Responses 路径不经过该转换网关；第三方 Responses 服务自身支持的工具和高级功能仍以服务商说明为准。此次更新不宣称完全兼容所有 Codex 功能。

## DeepSeek 官方能力限制

DeepSeek 提供 Responses 接口，但尚未完整支持 Codex 的全部工具能力。按其官方文档，自定义工具目前只支持 `apply_patch`；`exec` 等其他自定义工具会被拒绝并返回 400。联网搜索等部分内置工具也不在该接口的支持范围内。

因此，新建 DeepSeek Responses 配置可以绕过本地 Chat 协议转换，但不能保证所有 Codex 任务都可用。实际表现取决于 Codex 发出的工具类型与服务商能力。保存前会展示这项说明；此限制来自 DeepSeek 官方接口，不是通过调整本地转换网关即可消除的问题。

## 已有配置

移除预设不会删除已保存的服务和账号。已有 Chat Completions 配置不会静默改写：在 Providers 中选择“查看兼容性”，可预览官方地址和模型的变化，确认后原地切换到 Responses，保留服务名称、全部账号、密钥及账号选择。旧模型不在当前预设中时，会在确认框中明确展示建议的新模型。未知的自定义中转地址不会被自动替换，请先核对服务商支持的协议与模型。切换后建议新开 Codex 会话。

## 官方协议依据

于 2026-09-28 核对：

- [DeepSeek Responses 指南](https://api-docs.deepseek.com/guides/responses_api/)：基址 `https://api.deepseek.com`，默认 `deepseek-flash`。
- [智谱 Responses 兼容指南](https://docs.bigmodel.cn/cn/guide/develop/responses/introduction)：基址 `https://open.bigmodel.cn/api/v1`，默认 `glm-5.3`；旧 `/api/paas/v4` 为 Chat Completions 地址。
- [OpenRouter Responses API](https://openrouter.ai/docs/api/api-reference/responses/create-responses)：继续使用现有 Responses 路径与账号模型目录。
- [Requesty Responses API](https://docs.requesty.ai/api-reference/endpoint/responses-create)：基址 `https://router.requesty.ai/v1`，OpenAI 原生 Responses 模型使用 `openai-responses/` 前缀，默认 `openai-responses/gpt-5`。
