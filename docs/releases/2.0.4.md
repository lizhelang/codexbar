# v2.0.4：额度恢复后继续原线程

本版本在 2.0.3 基础上加入「额度恢复后自动继续」。功能默认关闭；确认账号和需要守候的线程后，Codexbar 会在明确的额度中断后等待服务端额度恢复，再请求原线程继续工作。

## 启用与账号确认

1. 在「会话」页或「设置 → 额度」中选择与 Codex 桌面端相同的当前账号。
2. 打开「额度恢复后自动继续」。默认的「桌面端当前账号（自动识别）」会显示识别出的账号，并在开启时固定其身份。
3. 展开「选择要守候的线程」，为需要继续的线程点击「确认守候」，明确确认该线程使用所选账号。

线程的创建账号不能代替当前账号确认。账号或连接方式变化时，守候会停止，需要重新确认。也可明确选择已经因额度耗尽停止的线程；其他旧任务不会自动接管。

身份核对同时检查工作区和登录用户。同一团队工作区内的不同用户不会共用续跑授权；无法确认用户身份时停止自动续跑。

## 等待与恢复

- 识别本机 Codex 桌面线程中明确的额度失败，保存等待记录，并按服务端重置时间重新查询额度。
- 恢复前查询新鲜、完整且属于所选账号的额度快照。五小时窗口已恢复、周窗口仍耗尽时，继续等待；不会仅凭本地倒计时放行。
- 通过 Codex 桌面端自带的 `codex queue` 继续同一个线程，沿用原线程的工作目录、模型与权限。
- 恢复记录区分「已入队，等待原线程实际运行」和「已确认原线程继续运行」。入队回执不等于线程已经运行。
- 应用重启后保留等待与发送记录；发送结果不明确时提示查看原线程，不自动重复发送。

## 取消与状态保护

- 可以取消单条等待、取消线程守候，或关闭整个功能。
- 检测到手动中断、归档、Goal 暂停、新输入或线程状态变化时，取消对应的待发送恢复；发送前还会重新核对线程状态与账号。
- 已提交的消息需要在原线程停止。关闭守候不会撤回已提交的消息。
- 记录损坏、保存失败、身份不明或额度信息不完整时停止自动放行，并显示需要处理的状态。

## 适用范围

支持本机 Codex Desktop 主线程，以及手动切换模式下明确绑定的 OpenAI 账号。聚合网关、远程线程、内部子代理和无法映射的独立模型额度暂不支持自动恢复。

电脑需要保持唤醒、联网，且 Codexbar 与 Codex 桌面端均在运行。电脑睡眠期间不执行检查，唤醒后重新确认状态。Codex 桌面端不具备所需续跑能力时，界面会说明原因。
