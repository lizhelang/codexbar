## DeepSeek 重复与刷新根因

本机 DSH 文件将同一凭据来源保存为旧 `deepseek` 和新 `deepseek-official` 两条余额快照。原实现按各自服务标识生成不同连接，因此展示两条；查询快照只重读文件，未访问实时余额接口。

现在仅归并这两个已知别名中凭据来源身份完全相同的记录，使用最新快照；相同金额不能证明同一账号，未知或不同身份仍保持独立。归并后的来源 ID 不依赖哪个别名最近更新。

自动 DSH 来源支持「隐藏此来源」及「恢复已隐藏来源」。隐藏仅写入 Codexbar 管理元数据，不删除 DSH 配置、凭据或快照；重启、重新发现和迟到请求不会使隐藏来源重新显示。

快照按钮明确为「重读快照」，保留原始余额时间。实时查询需当前明确的官方地址绑定或手动添加官方 API Key；历史名称不能授权发送 Key。自动凭据仅从当前绑定及当前用户私有文件读取，请求前再次核对绑定和指纹，并使用固定的官方余额接口。重复环境配置或根级 `refs` 的歧义会拒绝读取与发送。

本机只读见证返回 1 条来源、`officialLive=false`、0 次网络请求，保留 9 月 26 日原始快照时间。安装后的无凭据连接元数据也确认 **1 条可见 DSH 来源，类型为 `dshSnapshot`**。

本机有保存的 DeepSeek 凭据引用，但没有当前官方服务地址绑定，故尚未用它查询当前余额。已向用户询问要监测官方 API 还是中转站；用途未确认前不把原快照金额当成当前金额。未打印凭据，未向余额 API 发送该现有 Key。
