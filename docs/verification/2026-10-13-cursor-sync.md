# Cursor 用量分页同步修复验证

日期：2026-10-13（Australia/Sydney）

## 问题与修复

本机 Cursor 已登录，额度接口和用量首页均返回 HTTP 200，但历史同步失败，工具页保留 3,986 条旧记录，今天显示为 0。

原实现分页时未固定查询截止时间，Cursor 新增记录会改变总数和页边界；同时整轮仅允许 30 秒。实际诊断中一轮在第 12 页失败，随后服务端总数从 6,389 增至 6,390，另一轮完整成功。第一轮未记录具体完整性检查分支，因此不将其归因为已证实的超时。接口时间过滤已实测：固定过去截止时间返回 3,875 条，最新完整查询返回 6,391 条。

- 所有分页固定使用本轮开始时的截止时间，起始时间为 Unix epoch，以覆盖历史。
- 整轮接受预算调整为 120 秒并使用单调时钟；单页仍最多 15 秒，最后一页超预算也拒绝。
- 总数一致、重复页、完整数量、响应大小校验保持；失败仍保留该账号原有历史。
- 分页未完成单独显示原因，不再统一报告为账号接口不可用。

固定截止不能保证服务端迟到入库的原子快照，遇到截止前数据变化仍安全失败。120 秒是结果接受预算，不是强制中断流式传输的硬截止。
