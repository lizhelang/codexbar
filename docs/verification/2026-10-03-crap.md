### 每个方法的建议

1. **OpenAI 帧解析器**：优先补独立回归 fixture。先提取可测的纯 codec，再考虑拆分 header、长度、mask、控制帧校验；仅移动代码不降低复杂度。测试分片头、126/127 长度边界、极端长度及长度加法、保留位、未 mask、非 final 控制帧、无效 opcode、buffer 消费。解析器处理不可信输入，外围网关跨凭据/账号边界；需要后续真实回环 WebSocket 集成，普通 codec 单测不能验证 OAuth 上游。预期主要提高覆盖率，职责拆分后再降低单方法 C。不是普通低风险 UI 适配。
2. **设备 syncNow**：建议把模式策略、记录合并/缓存决策提取为纯函数并补协调器测试。覆盖 local/共享/iCloud/host/client、取消、revision 过时、重复同步、磁盘失败、服务错误、缓存保留。依赖文件系统、Task、网络和配对密钥；使用临时目录与回环 mock Hub，真实 iCloud/第二台设备另行验收。需要各模式 fixture 与独立失败回归，预期 C 与覆盖率一起改善。16 项关联测试主要验证其他底层部件，不能证明此方法受到保护。
3. **设置 label**：可用表驱动单测覆盖 key、工具名、语言和 unknown fallback；已经接近纯映射，无需先大拆分。若以后产品需要集中维护映射，可改 lookup 以降低 C；否则保持清晰 switch 即可。没有凭据边界或真实网络验证需求，普通映射 fixture 足够，优先级低于网关；预期主要增加覆盖率，不为分数改写可读映射。
4. **OpenRouter 帧解析器**：先用与 OpenAI 对应的协议 fixture 验证差异，再评估共享纯 codec，避免只为去重改变行为。补截断、mask、长度、控制帧和无效输入路径；这是网络输入边界，外围网关使用 provider 凭据。需要独立回归和回环帧验证，真实服务另行检查；预期先提高覆盖率，后续职责拆分可降低 C。不能因它是适配层就低估输入解析风险。
5. **用量 statusText**：建议提取纯状态/文案选择函数，补 availability × Cursor/其他工具 × refreshing × imported 的表格测试、nil 和失败/partial/sourceMissing。没有凭据写入，不需要真实 OAuth；离屏渲染可验证文本是否展示。拆分不是首要，状态组合 fixture 是首要；主要提高覆盖率，映射集中化后 C 可能降低。适配/展示风险有限。
6. **OpenAI 帧处理**：建议提取纯 fragment 状态转换和 action 决策，暂不强行重构全部网络循环。补 continuation 无前置帧、fragment 累积、text/binary、close/ping/pong、无效 opcode、send 失败、上游 cancel、sticky binding 清理。账号路由/凭据外围边界需要单独检查；mock transport + 回环集成分别提供单元和原生网络证据，不能替代真实服务端。需要协议回归 fixture，预期 C/覆盖率同时改善。
7. **OpenRouter 帧处理**：与上项同样先抽状态机，再补帧类型、fragment、错误、取消和 `Bool` 返回语义测试；特别核查两种网关结束策略的差异。外围 accountState/provider 凭据需独立审查。需要 mock + 回环，真实服务另行验收；需要单独协议回归，预期 C/覆盖率同时改善，不优先做无测试的统一抽象。
8. **OpenRouter SSE/WebSocket bridge**：建议把 SSE buffer/event 解析提取为纯函数，把转发/transport 保留为适配层。补跨包 delimiter、空 payload、[DONE]、EOF 尾块、非 UTF-8、非 2xx、非 SSE JSON、send/上游失败与关闭码 fixture。provider 认证在外围路径，错误载荷展示也需单独审查。用 mock byte stream 和本机回环验证，不访问真实服务；预期拆分 C 和提高覆盖率。不需要先推倒整个网关。
9. **Settings content**：这是 SwiftUI 页面路由 switch，已有 7 项设置离屏测试，并不证明每页路由覆盖。先补选页/展开的离屏用例和 page 枚举映射 fixture；不建议为降低 C 人为拆散 ViewBuilder。无需提取“纯函数”替代视图构造，除非页面选择规则今后变复杂。方法本身无凭据写入，但子页动作需要独立测试；系统权限行为仍需真实环境验证。主要提高可观察覆盖，适配复杂度合理，优先级低。
10. **设备 applyConfiguration**：优先拆纯验证/标准化、受保护文件持久化和 restart 三项责任。补名称/间隔/端口/目录/symlink、client URL、配对密钥长度/字符、保存失败、旧缓存清空与重启时序 fixture。涉及配对秘密和配置持久化边界，不能仅看分数；测试只使用合成密钥和临时目录，失败输出不包含秘密。需要独立持久化回归和本机 Hub 集成；当前未见要求修改格式的证据，不擅自迁移。预期降低 C 并增加覆盖率。
