# 对齐额度：本地验收

本地分支：`codex/quota-window-start`。基于上游 v1.2.18，独立修改 PR #50，未上传。当前测试版不包含尚未合并的 #53 浮窗修复和 #57 额度预留策略。

## 行为

- 设置 → 账号中新增“显示‘对齐额度’入口”，默认关闭，重启后保留用户选择。
- 打开开关只显示入口；只有手动点击才执行。使用 Codexbar 配置中的 OpenAI 默认模型，不追踪聊天的单独模型覆盖，不遍历旧模型名单。
- 请求前刷新额度；仅向尚未启动或旧窗口已结束的 5 小时额度账号发送独立短请求。进行中的窗口、其他窗口周期、额度不可用或无法确定状态的账号跳过。
- 发送 `ok`，要求只回复 OK，使用模型支持的最低推理档，无工具、不保存、不带会话标识，不切号；真实请求会消耗额度。
- 必须收到完整 `response.completed` 且响应状态为 `completed` 才计为请求完成。HTTP 2xx、流结束或 `[DONE]` 都不能单独证明完成。
- 请求后再次刷新额度。至少两个账号拥有有效重置时间，全部完成请求均可验证，且包括已运行窗口在内的重置时间差不超过 60 秒，才显示“已验证对齐”。否则显示请求完成但未确认对齐，或失败数量。

## 手动验收

1. 首次启动时，菜单没有“对齐额度”入口。
2. 在设置中开启并保存，菜单出现“对齐额度”；不开点击，不应产生启动窗口请求。
3. 退出并重新启动，开关仍开启；关闭保存后入口消失，重启仍关闭。
4. 默认模型设为你有权限的 OpenAI 模型，手动点击。若所有 5 小时窗口均在运行，提示“暂无可对齐窗口”，不应重置倒计时。
5. 有窗口尚未开始或已结束时，手动点击；请求完成后检查新倒计时与提示。只有一个账号完成、窗口时间不同或刷新失败时，不应显示对齐已验证。
6. 默认模型不可用时，应报模型不可用/请求失败，不静默改用 Luna 等其他模型。
