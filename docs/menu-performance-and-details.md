# 菜单响应与看板详情（1.2.19 / build 36）

## 点击入口

- 看板与管理共用固定位置的切换、刷新、末尾操作栏；管理加号位于切换左侧。
- 趋势图及“打开使用仪表盘”打开独立可缩放窗口，支持工具、日期范围、Token／费用、年度活动和模型／工具排行。
- 项目展开显示各工具用量、占比、费用和会话；模型展开显示输入、输出、缓存读写、缓存命中率和来源工具。
- 工具详情连接该工具的模型、项目和会话；设备展开按工具的汇总；会话展示来源、模型、项目、时间、运行状态和可用上下文信息。
- 无来源数据的字段标记未知；不通过 Token 用量反推订阅额度，不虚构消息数或活跃时长。

## 性能边界

- 菜单与设置打开只读取已经缓存的会话元数据，不能触发原始日志深扫描；用户手动刷新保留原有深扫描能力。
- 看板汇总及 SQLite 模型／会话查询在后台执行；每类工作最多一项执行、一项等待，等待项由最新选择替换。
- 周期与工具匹配后才显示新投影，避免把旧统计标成新范围。外观设置不触发数据重算。
- 原生 ScrollView 只渲染一份内容，用户设置的窗口高度独立于页面内容。
- 跨工具采集每轮只发布一次；相同设备统计不重复发布；同步缓存编码与写盘在串行后台队列完成。
- 项目与模型工具明细在投影时计算，展开时不扫描日志。设备聚合一次过滤同时产出总计和工具明细。

## 验证方式

- 数据回归覆盖时间范围、跨工具去重、项目明细总和、不同工具缓存计数语义、设备时区以及空缓存禁止扫描。
- 6,000 条工具记录的后台投影测试同时核对模型、项目、会话和总量一致。
- 原生菜单固定视口、仪表盘总览／趋势／最小窗口均使用隔离数据离屏渲染；这不等于用户桌面点击延迟测量。
- 安装后的进程采样应与修改前使用相同物理内存口径比较；短暂空闲样本不代表所有工作负载。
